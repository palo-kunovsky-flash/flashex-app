Privacy & security

Flashex has no telemetry, no analytics, no accounts and no crash reporting. It sends nothing about you or your work anywhere.

AI help

Nothing is sent until you press Return on a # … line at a prompt, or click Explain, Fix, Send to AI… or Test connection.

  • # → command sends what you typed after #, your operating system, your shell's name and the current folder (as ~/…). Your last command and its exit code only if you turn on send_last_command, and never when it looks like it contains a secret.
  • Explain, Fix and Send to AI… send that block's command, folder, exit code and output, trimmed to its first and last lines (output_lines, output_kb), with passwords, tokens and keys replaced by ***.
  • Where it goes is your provider: the claude, codex or gemini program on your computer (under your own login and their terms, run in an empty temporary folder with no tools it could act with); your own command on its standard input; or an OpenAI-compatible server at base_url, which with a local model never leaves your computer. HTTPS is required except for localhost, 127.0.0.1 and ::1.
  • Send to Claude / Codex / Gemini with an agent running in a terminal only types the text there; it is sent when you press Return.
  • The API key is kept in the macOS Keychain (Windows: the Credential Manager; Linux: a file only you can read), never in config.toml, and is sent only to your server.
  • Suggestions from your history are computed on your computer and never sent.

What Flashex reads and keeps on your computer

  • The Usage dashboard reads Claude Code's transcripts (~/.claude/projects or the account's folder) while it is on screen: only timestamps, model names, token counts, the length of visible text, the session id and the last name of the working folder. No message text is kept or logged. To label accounts it reads the e-mail and organisation name from each folder's .claude.json, never a token.
  • The status line script Flashex installs when you press Apply keeps only the rate limits out of what Claude Code hands it, writes them to a file in ~/Library/Caches/flashex and sends nothing anywhere.
  • Claude Code's settings.json is changed only when you install hooks or apply the status line (a backup is kept next to it), and when Flashex updates hooks it installed earlier.
  • The System dashboard reads this Mac's counters in-process, without root, and runs ps and nettop only while it is on screen. Nothing is stored; chart history lives in memory.
  • The chat over an agent's terminal reads that agent's own transcript and the pictures a reply names, on your computer.
  • The account switcher, once turned on, keeps each Claude Code login in the system's secret store (the macOS keychain, Windows' Credential Manager, on Linux a file only you can read) and what is not secret (e-mail, organisation, plan, the limits last read) in claude-accounts.json in Flashex's data folder. With it off, no login is kept.
  • Artifacts: Flashex's Claude Code hooks note every page Claude publishes and keep a local copy in Flashex's data folder (each artifact's latest version, five older ones of the last 90 days, 500 MB in all). [agents] artifacts = "local" keeps pages on this computer only. Local artifacts, the HTML, SVG and PDF pages an agent shows you on this computer, are kept the same way (with what they name in their folder put inside the copy) and never leave it except to your paired phones; only your own files in your home folder or a temporary folder, never one only written, and [agents] local_artifacts = false turns it off.
  • Todos are Markdown files in Flashex's data folder; they leave this computer only to the computers you paired with Sync.
  • Search Agent Sessions keeps an index of words and their places, not your conversations, in the data folder; Command History keeps your favorites and labels there.
  • Remote Access keeps each paired phone's and computer's name, level and public key in the data folder (remote-access/); the phone's own key never leaves the phone. The Vault, Flashex's API socket and files that look like secrets (.env, keys, .ssh, .git) are never reachable from a phone.

The Vault

The Vault (command palette › Vault…) keeps secrets in one encrypted file in Flashex's own folder on your Mac, ~/Library/Application Support/flashex/vault/vault.fxv, never in the cloud and never in the macOS Keychain. Without your vault password the file is unreadable: the content is encrypted with XChaCha20-Poly1305 and the password is stretched with Argon2id. The last three versions of the file are kept next to it as backups; changing the password removes them, but copies elsewhere (Time Machine, other backups) still open with the old password, with the content they had then.

Touch ID is optional. Turning it on stores a key in your login keychain that opens the vault without the vault password; Flashex asks for your fingerprint before it reads that key, but the check happens inside Flashex. With Touch ID on, the vault is as strong as your macOS login password and keychain: a program you allowed to read Flashex's keychain item ("Always Allow"), for example security find-generic-password, could read the key. Adding or removing a fingerprint turns Touch ID off for the vault.

The Vault does not protect against a program running as you while the vault is open, a keylogger, or a program you allow to read a value: it gets the value and can keep it.

Everything in an entry is inside that encrypted file: its secret fields, and also its name, note, tags, URL, username and dates. Search never looks at secret values. To point out a secret stored in two entries, Flashex compares keyed hashes of the values (with a random key made at each unlock) in memory while the vault is open; no hash is written anywhere. Generated passwords and tokens come from the operating system's random number generator. Import .env… reads the file you name (never through a symbolic link), adds its values as entries, and then offers to delete it, checking first that it is still the file it read; when the vault does not hold every value of it, deleting needs a second confirmation. Copies of it elsewhere (backups, version control history) are not touched. Export… writes only an encrypted copy of the vault, opened with the vault password and not with Touch ID; Flashex has no plain-text export. When you Copy a value or allow a request, the entry's "last used" time is noted in the vault.

Security

  • The flashex command talks to the app over a Unix socket that only your user can open (0600, in a 0700 folder). [api] enabled = false turns it off.
  • Programs in a terminal may write to the clipboard (OSC 52, clipboard_write) but can never read it.
  • Shell integration marks are signed, so programs cannot fake command blocks.
  • Command lines that look like they contain a secret are never saved in the session, offered to run again or suggested from history.
  • Updates are verified with Flashex's own signature, the exact size and SHA-256, and the new app's code signature before they replace anything (Updates).
