Troubleshooting & FAQ

Common problems and how to solve them. Anything else: open an issue.

macOS says Flashex cannot be opened

A downloaded copy needs one confirmation, because Flashex is not notarized by Apple. Right-click Flashex in Applications and choose Open, then Open again, or run xattr -dr com.apple.quarantine /Applications/Flashex.app. Homebrew does this for you. See Opening it the first time.

flashex: command not found

Inside a Flashex terminal the command is always there. Outside it, Homebrew links it; after a dmg install, link it yourself: ln -s /Applications/Flashex.app/Contents/MacOS/flashex /opt/homebrew/bin/flashex.

The flashex command exits with code 2

It could not reach Flashex: the app is not running, or the window's API is turned off ([api] enabled). Inside a Flashex terminal a command only ever talks to that window. See Exit codes.

The sidebar shows no state for Claude Code

  • Install the hooks: flashex setup claude, or Settings › AI agents › Claude Code hooks. Sessions started before pick them up on their next start.
  • Using an alias with its own CLAUDE_CONFIG_DIR? Pick that account in Settings › AI agents › Claude account and install the hooks there too (Claude accounts).
  • If the hooks row says they are outdated or customised, Update brings them up to date.

The Usage dashboard does not show my rate limits

They come from Claude Code's status line. Press Set up in Settings… (or Settings › AI agents › Claude Code status line › Apply); the limits appear after a session's next answer. If the row names a project or managed settings file, that file sets its own status line there. Alternatively turn on usage_api.

My terminals were not kept when I quit

Check Settings › Session › Terminals when Flashex quits (keeper_on_quit), and that keeper and restore are on. Kept terminals end after keeper_grace_minutes, and logging out or restarting the Mac ends them. flashex keeper status shows what is kept right now.

I want to end terminals kept in the background

Run flashex keeper stop: it ends the terminals held while Flashex is closed, without opening it. A running Flashex's terminals are left alone; quit Flashex with Quit and End All to end them.

A terminal lost Screen Recording or Accessibility

macOS gives these permissions to the process that started a terminal's shell. Since 0.2.1 that is Flashex's helper, so they survive restarts and updates; terminals started by an earlier version do not get them back (open a new terminal). After updating to 0.2.0 from an earlier version, grant the permissions once more in System Settings › Privacy & Security; later updates keep them.

Notifications show a blank white icon

macOS is holding an old copy in its icon cache. Run sudo rm -rf /Library/Caches/com.apple.iconservices.store in Terminal and restart your Mac.

Notification banners disappear too fast

How long they stay is set by macOS. Settings › Notifications › Keep notifications on screen › Open, then choose Alerts.

Ctrl+Space does not open completions

With several input sources, macOS takes ⌃Space to switch between them. Use ⌥Esc, which asks for completions too.

A shortcut does something else, or nothing

⌘? lists every shortcut in effect. Shortcuts you change in keybindings.toml that cannot work (an unknown action, a key the shell needs) are reported with their line number and left out. See keybindings.toml.

A language has no errors or completion

Flashex uses servers already installed on your system. The palette's Language Servers… shows which are found and how to install the missing ones. In a folder that is not one of your projects, servers that run code ask first.

My config.toml change did nothing

Changes apply as soon as you save. An unknown setting, a wrong value or a file that is not valid TOML is reported in a notice, with its line where it is known. Some settings apply to new terminals or at the next start (each says so in the reference).

Where are the logs and data?

Settings: ~/.config/flashex. App data (session, backups of unsaved editors, the restart keeper): ~/Library/Application Support/flashex. Caches: ~/Library/Caches/flashex. Logs: ~/Library/Logs/flashex. Attach the log to a bug report if it helps (check it for anything private first).

The AppImage does not start on Linux

It needs FUSE (fuse3 / fusermount3). Without it, run it with --appimage-extract-and-run, or use the .deb or .tar.gz.

FAQ

Is Flashex free?

Yes, for personal and commercial work. It is closed source: the public repository holds the README, these docs, the screenshots and the releases. The terms are in the LICENSE.

Do I need an API key for the AI features?

No. Flashex uses Claude Code, Codex or Gemini CLI with their own login, your own command, or a local model server. An API key is only needed for a hosted OpenAI-compatible server you choose.

Does it work with agents other than Claude Code?

Yes. Any agent runs in a terminal and can notify (OSC 9, 777, 99, a bell, flashex notify) or report its state (flashex agent). The hooks, the dashboards, resume and reload are for Claude Code.

Does it run on Intel Macs or Windows?

No Intel Macs. Linux is in beta; Windows is planned.
