Projects and the sidebar

A project is a folder with its own tabs and layout. The sidebar lists them, optionally in groups, with what runs in each.

Projects

+ Project at the foot of the sidebar, ⌘N or New Project… in the palette opens the New project dialog:

  • It lists folders it found, tagged as an open project, a terminal's folder, a git repo or recently closed (picking a closed project brings it back with its tabs). Type to filter, or type a path such as ~/Dev/app or /opt/work: it shows at the top as soon as it exists.
  • Choose Folder… opens the macOS folder panel. ⌘O opens that panel directly.
  • The Group field picks the group the project goes in: Tab and ⇧Tab step through your groups and "No group".

Picking a folder that is already a project switches to that project (and moves it into the chosen group).

Making a new folder

New Folder… in the dialog opens a small form: the folder's name, where it goes (next to your last project's folder, or your home folder; type a path or click Choose…) and Initialize git repository (ticked when git is installed). Create and Open makes the folder and opens it as a project in the chosen group. A name with a /, a folder that is already there or a location you cannot write to is reported in the form, and nothing is made. Tab moves between the fields, Space ticks the box, Return creates, Esc cancels.

A project's menu

Right-click a project in the sidebar for Rename, its colour, Set Project Folder…, Move to Group…, Remove from Group and Close Project. The menus work from the keyboard too: ↑ ↓ to choose, Return or Space to run, Esc to close.

Colours. A project or group gets a colour automatically; pick another from the swatches (Blue, Indigo, Teal, Amber, Orange, Green, Purple, Cyan, Red, Pink, Lime, Brown, Slate, Gray) or Custom…, where you type a hex value (#3B82F6, #F80) or pick one with the mouse. The palette's Set Project Color and Set Group Color do the same from the keyboard.

Groups

+ Group or ⇧⌘N makes a group. Drag projects into it, or use a group's + (shown on hover, always for an empty group), its Add a project… row, or Add Project… in its right-click menu: the New project dialog opens with that group chosen. A group's menu also has Ungroup (keeps its projects) and Close Group (closes them, asking first). Click a group's header to fold it.

What a project's row shows

  • The branch of the project's repository with ↑ commits to push, ↓ commits to pull and ± changed files (main ↑1 ±4); hover for the same in words.
  • Unread notifications as a count, and the state of its agent as a dot.
  • Its terminals, editors and browsers underneath ([sidebar] show_terminals), each with its agent's state and unread notifications. The chevron on the project's row folds the list; a long list ends in "+N more". A terminal's row has a right-click menu with Rename and Close, and the rows of the tab on screen can be dragged into a pane.

Web server chips

When a program in a terminal serves web pages (npm run dev, python3 -m http.server, an ssh -L tunnel), a small chip with a globe and its port appears on that terminal's row: ◍ 5173. Its tooltip names the program; a click opens the page in a browser panel. With several servers the chip shows the first and "+2", which lists the others. While the terminal's row is folded away or behind "+N more", the chip sits on the project's row instead. In a narrow sidebar it is the globe alone.

Flashex asks each new port once with a short local HTTP request and shows only the ones that answer like a web server, so debuggers, IDE bridges and the ports agents themselves listen on are left out. Open Port in Browser… in the palette lists all of the project's servers.

Workflows

A workflow is a saved command with optional parameters. Save one from a command block's tools, or with Save Last Command as Workflow…; run them from ⌘K; Manage Workflows… edits, duplicates, moves and deletes them. They live in ~/.config/flashex/workflows.toml (every project) or <project>/.flashex/workflows.toml (that project only, and it wins over a global one of the same name):

.flashex/workflows.toml
[[workflow]]
name = "deploy"
command = "./deploy.sh {{env:staging}}"
description = "Deploy to an environment"

Parameters are {{name}} or {{name:default}}, filled in at the prompt with Tab.
