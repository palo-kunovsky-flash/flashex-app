Configuration

Flashex reads ~/.config/flashex/config.toml and applies changes as soon as you save.

The file

The file is created at the first start with a comment for every option. Settings (⌘,) edits the same file and keeps your comments, so you can use either. Settings that only apply to new terminals or at the next start say so in their comment. An unknown setting or a wrong value is reported in a notice with its line.

~/.config/flashex/config.toml
[appearance]
theme = "system"          # dark | light | system | graphite-dark | …
accent = "orange"         # green, blue, indigo, teal, amber

[terminal]
font_family = "Geist Mono"
font_size = 13

[session]
keeper_on_quit = "ask"     # keep terminals running after a quit

Other files

FileWhat it holds
~/.config/flashex/keybindings.tomlYour shortcuts: Keyboard shortcuts.
~/.config/flashex/layouts.tomlLayout templates: Layouts and templates.
~/.config/flashex/workflows.toml, <project>/.flashex/workflows.tomlSaved commands: Workflows.
~/.config/flashex/themes/Terminal colour themes (key = value lines such as background = #1e1e2e and palette = 1=#f38ba8). Settings › Appearance › Import a terminal color theme copies one here; theme names it.
~/Library/Application Support/flashexApp data: the session, backups of unsaved editors, the restart keeper's folder.
~/Library/Caches/flashex, ~/Library/Logs/flashexCaches (the Usage dashboard's summary, status-line data) and logs.

Themes and colours

theme takes dark, light, system (follows macOS, the default), one of Flashex's colour schemes (graphite-dark, graphite-light, harbor-dark, harbor-light, ember-dark, ember-light), or the name of a theme file in ~/.config/flashex/themes. "light:<name>,dark:<name>" picks one for each macOS appearance. The accent can be orange, green, blue, indigo, teal or amber.

Reference

Every section and key, generated from the defaults Flashex writes. Each table lists the keys with the value the new file has (or the commented-out example); the pane under it is the section exactly as the file has it, with what each option does.

[session]

KeyIn the default file
restoretrue
offer_reruntrue
keepertrue
keeper_grace_minutes10
keeper_on_quit"ask"

keeper_relaunchfalse
keeper_spawnstrue commented out
config.toml · [session]
[session]
# Reopen groups, projects, tabs and splits from the last run.
restore = true
# A restored terminal offers to run again the command that was running in
# it (never by itself). Command lines that look like they hold a secret
# (KEY=..., export, --password, token, Authorization...) are never kept.
offer_rerun = true
# Terminals survive a crash, "Restart Flashex" or a quit: a small helper
# keeps them until Flashex is back, at most keeper_grace_minutes; then it
# ends them. Takes effect at the next start.
keeper = true
keeper_grace_minutes = 10
# What quitting does with the terminals: "ask" keeps them running and asks
# first when programs still run in them, "keep" keeps them without asking,
# "end" ends them. A quit asked for by macOS or another program (Quit &
# Reopen after a permission was granted) keeps without asking; logging
# out, restarting or shutting down ends them.
keeper_on_quit = "ask"
# Output kept per terminal while Flashex is gone, MB (the oldest goes).
keeper_buffer_mb = 4
# After a crash, start Flashex again by itself (once).
keeper_relaunch = false
# That helper starts the shells (and is then Flashex itself, a second
# flashex-app process), so the macOS permissions given to Flashex
# (Screen Recording, Accessibility, Files) stay with a terminal when
# Flashex restarts, is updated or crashes. On by default on macOS, off
# on Linux and Windows. With false, Flashex starts the shells itself and
# programs in a terminal that outlived Flashex lose those permissions.
# Takes effect at the next start.
# keeper_spawns = true
