CLI reference

flashex controls the running app from a shell, a script or an agent's hook. Every command answers --help with its own usage.

Which app it talks to

  • Inside a Flashex terminal, FLASHEX_SOCKET names that window's socket and FLASHEX_PANE_ID the terminal. Commands target that terminal unless you pass --surface. A command never falls back to another Flashex.
  • Outside Flashex, the default socket: ~/Library/Application Support/flashex/flashex.sock on macOS; on Linux $XDG_RUNTIME_DIR/flashex/flashex.sock, else ~/.local/share/flashex/flashex.sock.
  • The socket is 0600 in a 0700 folder, so only you can connect. [api] enabled = false turns it off.

Ids. flashex list shows projects, tabs, panes and terminals with their numeric ids. A terminal's id is called a surface. -- ends the options, so text after it may start with -.

Exit codes

CodeMeaning
0Done.
1An error: bad arguments, an unknown id, a refused request (the message says why).
2Flashex is not running (no socket, or this window has its API turned off); for events, also when the app closed the stream.

Commands

flashex list [--json]

Lists projects, tabs, panes and their surfaces (terminals, editors, previews, browsers), each named as its pane tab shows it. * marks the active project and > the focused surface; an agent's state is shown in brackets. --json prints the API's answer as is.

flashex notify [--surface N] [--title T] [BODY]

A notification for a terminal: a highlighted frame, a dot on its tab and a count in the sidebar, and a system notification when you cannot see that terminal. Only a terminal takes one; without --surface it goes to the terminal the command runs in, else the one you used last. --from-claude-hook is what Claude Code's hooks run (see setup claude); a hook always exits 0, so Claude Code is never interrupted.

zsh
❯ make test; flashex notify --title Tests "finished with $?"

flashex agent [--surface N] <running|waiting|idle|error>

Sets the agent state shown in the sidebar, for agents without Claude Code's hooks.

zsh
❯ flashex agent waiting

flashex status [--surface N] [TEXT]

A status line for the terminal's project. Without text, the status is cleared.

flashex focus <SURFACE>

Shows a terminal: its project, tab and pane. The window comes to the front.

flashex send [--surface N] TEXT

Types text into a terminal. \n, \r, \t, \e and \\ are decoded, so flashex send 'ls\n' runs ls.

flashex read [--surface N | --caller] [--last-block | --scrollback N]

Prints a terminal's text:

  • no option: the visible screen;
  • --last-block: the output of the last finished command (needs shell integration); exits 1 when there is none or its output left the history;
  • --scrollback N: the last N lines up to the cursor's line, history included (at most 100 000). A wrapped line counts once.

Both read the shell's text also while a full-screen program shows its own. --caller reads the terminal the command runs in (it fails outside Flashex). Without --surface or --caller, it reads the terminal it runs in, or the focused one outside Flashex.

zsh
❯ cargo build; flashex read --last-block > build.log
❯ flashex read --surface 12 --scrollback 200 | grep -i error

flashex open [--project N | --surface N] PATH[:LINE[:COL]]

Opens a file in the editor, as ⌘-click does. If it is already open, its tab is shown; otherwise it opens in the tab's editor pane, or in a new split to the right. A relative path is resolved against the folder you run the command in. --project opens it in that project; --surface beside that terminal. A missing file or a folder is refused (exit 1), and nothing in the window moves.

zsh
❯ flashex open src/main.rs:120:8

flashex browse [--project N | --surface N] URL|FILE

Opens a web page in a browser panel: a new tab of the tab's browser pane, or a split beside the terminal. Any http:// or https:// address works; one without a scheme gets http://. A local HTML, SVG or PDF file opens too: ./index.html, ~/site/index.html, an absolute path, a file name in the current folder or a file:// address (a folder opens its index.html). Other schemes are refused. The new panel's id is printed. Without the browser panel (Linux), the page opens in the system browser.

zsh
❯ flashex browse localhost:3000

flashex events [--type T[,T…]] [--surface N]

Prints the app's events, one JSON object per line, until Ctrl+C. When stdout closes (| head -1) it exits 0; when the app closes the stream it exits 2. --type keeps only the named types; --surface only one terminal's events. At most 16 streams may be open at once.

typeFields
notificationsurface, title, body, bell (true for a BEL)
agentsurface, state (running, waiting, idle, error)
command-startedsurface, command, cwd (needs shell integration)
command-finishedsurface, command, cwd, exit_code, duration_ms
cwdsurface, cwd (the shell's folder changed)
focussurface (another terminal, editor or panel got the focus)
laggeddropped: this many events were lost because the reader was too slow

Events of one type and one terminal come in the order they happened; across types the order is only close, so compare by terminal and type.

zsh
❯ flashex events --type command-finished | while read -r ev; do echo "$ev" | jq .exit_code; done

flashex new-tab [--cwd DIR]

Opens a tab in the caller's project (in DIR if given) and prints the new terminal's id.

flashex split <right|down|left|up>

Splits the terminal and prints the new terminal's id.

zsh
❯ id=$(flashex split right) && flashex send --surface "$id" 'npm run dev\n'

flashex size [--surface N] [cols|rows] <N|N%>

Pins the size of the terminal's pane, as dragging its divider does: N columns or rows (1–2000), or N% (1–99) of its split. The size applies in the innermost split around the pane; cols or rows picks the nearest split in that direction. The pane keeps the size when the window is resized, until a divider is dragged or the split is equalized. Prints nothing.

zsh
❯ flashex size 60%          # the innermost split
❯ flashex size rows 12      # 12 rows high

flashex setup claude [--yes] [--print]

Adds Flashex's hooks to Claude Code's settings ($CLAUDE_CONFIG_DIR/settings.json, else ~/.claude/settings.json), so Flashex shows when Claude Code is working, waiting or done. It shows the change (a line diff of the hooks part) and asks first; --yes skips the question and --print only shows the change. Running it again is safe: older Flashex hooks are updated in place, missing ones added, current ones left alone, and your other hooks, keys and formatting stay. The old file is kept as settings.json.flashex-backup and, the first time, settings.json.flashex-backup.orig. A symlinked settings.json keeps its link; a read-only one is left alone.

zsh
❯ CLAUDE_CONFIG_DIR=~/.claude-work flashex setup claude

flashex keeper status [--json]

Lists the restart keepers (the helper that keeps terminals running across a crash, Restart Flashex or a quit) and what each holds: its process id, the Flashex version that started it, whether it is attached to a running app or holding terminals for the next one (and why), how many terminals it keeps and how many still run, how much output it has buffered and how long until they are stopped. It asks the keepers directly, so it works without a running app. It only looks.

zsh
❯ flashex keeper status
Restart keepers in /Users/me/Library/Application Support/flashex/keeper:
  keeper 4242 (Flashex 0.2.1): holding 3 terminals for the next app (Flashex was quit), 3 running, 1.2 KB buffered, stopped in 9 min 20 s unless Flashex is opened

flashex keeper stop [--json]

Ends the terminals a keeper holds while Flashex is closed, and that keeper, without opening the app. A keeper that belongs to a running Flashex is left alone, and the command says so. The exit code is 1 when a keeper did not stop.

zsh
❯ flashex keeper stop
Ended 3 terminals kept by keeper 4242 (3 running).

flashex vault list, get, run, env

Secrets from the Vault (command palette › Vault…). flashex vault list [--json] prints the entry names, never values. flashex vault get [-n] [--print] NAME prints an entry's main secret (an API key's value, a login's password, an SSH key's private key) into a pipe or a file; to a terminal only with --print. flashex vault run VARS… -- COMMAND [ARGS…] runs a command with values in its environment. flashex vault env [--format dotenv] [--print] VARS… prints KEY=VALUE lines into a pipe or a file (> .env.local); to a terminal only with --print.

VARS, any number and mixed: --env VAR=ENTRY puts the entry in $VAR; --env ENTRY or --entry ENTRY puts it under its own variable name (the Variable you set on an API key, such as OPENAI_API_KEY, else the entry's name); --all-tagged TAG puts in every entry with that tag that has a variable name.

For get, run and env Flashex brings its window forward and asks: which entries and which variables they go into, which process (its name, pid and program, and its parent's, as the system reports them), and what the command says about itself (its terminal, the command it will run, and with env --print that it prints the values on the terminal: shown as claims). Nothing is sent until you press Allow. A locked vault is unlocked in the same card first; list waits only for that. The command waits up to 90 seconds; Deny, no answer, or too many requests waiting ends it with exit code 1.

Careful with values on screen. A value printed in a terminal stays in its scrollback, which flashex read returns without asking and which survives a restart. Prefer vault run, a pipe (flashex vault get GH_TOKEN | pbcopy) or Copy in the Vault. Flashex checks only where flashex itself writes: | tee, | cat or vault run -- printenv still put values on the screen after you allow them. Values in a command's environment can be read by other programs running as your user while it runs.

zsh
❯ flashex vault run --env OPENAI_API_KEY -- python agent.py
❯ flashex vault run --all-tagged ci -- make deploy
❯ flashex vault env --entry openai --entry anthropic > .env.local

flashex --version, flashex --help

Print the version, or the usage of every command.

The socket API

Programs that can write to a Unix socket can use the same API directly: JSON-RPC 2.0, one message per line.

request
{"jsonrpc":"2.0","id":1,"method":"read","params":{"surface":3,"last_block":true}}

Every answer is one line too: {"jsonrpc":"2.0","id":1,"result":{…}} or an error with a code and message. A request without an id is carried out but not answered. A request may be at most 1 MiB; an idle connection closes after 120 s; at most 64 connections may be open. surface is optional wherever it appears; the default is the focused terminal.
