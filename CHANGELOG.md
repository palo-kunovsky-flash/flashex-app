# Changelog

All notable changes to Flashex are listed here, newest first.
Each version links to its release, where the dmg, its SHA-256 and the signed update manifest are attached.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/): **Added** for new features, **Changed** for changes to existing behaviour, **Fixed** for bug fixes, **Removed** for features that are gone, and **Security** for anything that affects your safety.
Versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

## [0.2.1] - 2026-10-14

Quitting Flashex no longer ends your terminals, terminals keep Flashex's macOS permissions after a restart or an update, and Claude Code sessions resume under the account they were started with. macOS only; the Linux beta stays at 0.1.2 for now.

### Added
- **Usage: pick the Claude account.** Claude Code keeps one account per folder: `~/.claude`, or the folder an alias sets with `CLAUDE_CONFIG_DIR` (a personal and a work login, say). When Flashex finds more than one (`~/.claude`, and `~/.claude-*`, `~/.claude_*` or `~/.config/claude*` folders that hold transcripts or a login, the folder your shell exports, and any listed in `[agents] claude_accounts`), the Usage dashboard shows a row of account chips, each with its folder and the e-mail logged in there. Transcripts, rate limits and the status-line data are then read for the account you pick, and the choice is remembered (`[agents] claude_account`). With one account nothing changes. Until now only the default folder was read, so with aliases the dashboard could stay empty. The usage API (when turned on) still only knows the default account's login; another account gets its limits from its status line.
- **Settings › AI agents: Claude account, and hooks per account.** A new "Claude account" row shows which folder the rows under it work with (`←`/`→` or its arrows pick another). "Claude Code hooks" now installs into and reports on that account's `settings.json`, so a session started through an alias can show up in the Agents dashboard too. Hooks already installed in an account that is in use are still brought up to date at start.

### Changed
- **Quitting keeps your terminals running.** Quitting Flashex used to end every terminal and whatever ran in it, also when macOS itself quit the app ("Quit & Reopen" after you allow Screen Recording in System Settings), so running agents were lost. Now the terminals go on running without the app, the same way they do through an update or "Restart Flashex", and opening Flashex again brings them back with what they showed and what they printed meanwhile. They wait for `keeper_grace_minutes` (10 by default, up to a day; `[session]` in the config), then they are ended; if any of them was running a program, the next start says so. When programs are still running, Cmd+Q, the menu and the window's close button ask first and name what runs: **Quit and Keep Running** (the default; Return or Cmd+Q again), **Quit and End All**, or Cancel. If one of them is a Claude Code session started with `--dangerously-skip-permissions`, the question says so and has no default: you choose. With nothing running Flashex quits at once and keeps them. If the helper that keeps them cannot, Flashex does not quit and tells you. A quit that comes from outside (Quit & Reopen, the Dock, a script) never asks and keeps them; when programs were running, one system notification says how many terminals are kept and for how long (unless `[notifications] system` is off). Logging out, restarting or shutting down the Mac ends them, as nothing would bring them back, and no longer stops for unsaved files that hot exit keeps anyway. Settings › Session has a new row, **Terminals when Flashex quits** (`[session] keeper_on_quit`): "Keep, ask if busy" (`"ask"`, the default), "Keep" (`"keep"`, never asks) or "End" (`"end"`, as before). Terminals are kept only while "Keep terminals running through a crash, restart or quit" and session restore are on.
- **`flashex keeper stop`.** Ends the terminals that are kept while Flashex is closed, without opening it; the terminals of a running Flashex are left alone. `flashex keeper status` now says why terminals are held and how long they have left.
- **The offer to resume shows what it will run.** Under "Resume the Claude Code session that ran here", the line used to start with `cd` and the whole folder, so a narrow pane showed only the folder. It now starts with the command (your alias, the session, options such as `--dangerously-skip-permissions`) and ends with the folder, shortened in the middle; point at it for the full line. With more than one Claude account the default one is called "default" instead of "~/.claude", here and in the Agents dashboard, and the question no longer leaves a lone "?" on its own line.
- **The status line is set up in Settings, not by pasting code.** The Usage dashboard no longer shows a block of shell code to paste into your status-line script. When the rate limits are unknown it says so in a sentence, with a **Set up in Settings…** button. Settings › AI agents has a new row, **Claude Code status line**, with **Apply** and **Remove**: Apply points the account's status line at a small script in Flashex's own folder, which saves the limits Claude Code reports, and nothing else, on your computer (nothing leaves it). A status line you already have keeps running and showing exactly as before, inside Flashex's; Remove takes Flashex's entry out and puts your status line back. Both ask before writing, back `settings.json` up first, and refuse a file that is read-only or not valid JSON. If you pasted the earlier lines by hand they keep working; the row says "Set up by hand".
- **Usage: the 5 h and 7 d limits side by side.** In a wide Usage pane that is not yet wide enough for two columns of cards, the two limits now stand next to each other instead of under each other with an empty half of the card beside them. A narrower pane shows them one under the other as before.
- **"Grow Pane Left / Right / Up / Down".** The commands that resize the focused pane from the keyboard (`Cmd+Ctrl+arrows`) were listed as "Grow Left" and so on in Keyboard Shortcuts and the command palette; their names now say what they grow. Each moves the pane's edge on that side, so it does nothing where the pane has no neighbour there, and like a dragged divider it keeps the split as a ratio.
- **System: cards keep their height.** A card in the System dashboard no longer grows and shrinks as its content comes and goes. A network interface that moves a few bytes for a moment (a VPN tunnel, for example) is not listed at all; one that stays for about six seconds is, and it then keeps its row, idle, for five minutes after it went quiet. The interface, talkers and process tables keep room for the most rows they had in the last five minutes, both process tables are the same height (so switching between CPU and Memory moves nothing), and the disk's "full on …" line, the note on processes read with `ps` and a temperature group that did not answer keep their place. A card gives the room back once, after five quiet minutes.

### Fixed
- **Tabs no longer move when a command starts or ends.** Every command changes its tab's title ("proj" becomes "proj — sleep" and back), and the tab grew and shrank with it, pushing the tabs after it along each time. A title now has to stay for a second before its tab takes it: a quick command (`ls`, `echo`) leaves the row as it was, and a long one widens its tab once. A title as short or shorter shows at once in the tab as it is, so Claude Code's working spinner still turns, and the tab narrows only once the shorter title stayed.
- **A tab's unread dot no longer cuts its name for a moment.** When a tab got its unread dot, its name was shortened to "pr…" for a frame while the tab grew; the tab now makes room for the dot at once.
- **Claude Code's hidden cursor stays hidden after a quit or restart that kept it.** Back in Flashex, a terminal kept running with Claude Code in it showed a terminal cursor under Claude's prompt box until Claude drew again. What a kept terminal shows when Flashex comes back now also sets what the program had set: its cursor hidden and where it was, bracketed paste, focus reports, mouse reports and its keyboard mode, so pasting into Claude Code keeps working the same after Flashex is reopened.
- **A quit that cannot keep the terminals says so at once.** When the helper that keeps terminals did not answer, Flashex stood still for five seconds per terminal before saying it did not quit; it now says so after one try.
- **The full resume line on hover.** In a narrow pane, the line under "Resume the Claude Code session that ran here" can be cut (`claude --continue --dangerous…`); pointing at it now always shows the whole line, not only when the folder was shortened.
- **Terminals keep Flashex's macOS permissions after Flashex restarts or updates (macOS).** Programs in a terminal that kept running while Flashex restarted, was quit and opened again, was updated or crashed lost the macOS permissions you gave Flashex (Screen Recording, Accessibility, Files, Automation): macOS counts them to the process that started the terminal's shell, and that was the window, which was gone. `screencapture`, for example, then captured only the desktop picture. Now the shells are started by the small helper that keeps terminals running, and that helper is Flashex itself (you will see a second `flashex-app` process, with no Dock icon). It is there from the moment a terminal opens until it closes, and Flashex opened again joins it, so a terminal keeps Screen Recording, Accessibility and the rest, also one that was already open when you granted a permission and chose Quit & Reopen. After an update the helper of the old version stays only until the terminals it started have closed; new terminals belong to the new one. Terminals started by an earlier version of Flashex do not get their permissions back: the notice that terminals were reconnected says which ones lost them, and a new terminal has them. To have Flashex start the shells itself as before, set `keeper_spawns = false` under `[session]` in the config and restart Flashex. Linux and Windows are unchanged.
- **A kept terminal's tab has its program's name at once.** Back in Flashex after a quit, restart or update, a terminal with Claude Code in it was called "projB — claude" until Claude set its title again; it is "✳ Claude Code" (or the conversation's topic) right away. When the program ends after that, the title from before it comes back, as it does without a restart.
- **After a crash of Flashex, a terminal's program finds its terminal as it left it.** Terminals survive a crash, but what the program had set did not: Claude Code's hidden cursor showed under its prompt box, and its paste, mouse and keyboard modes, a full-screen program's screen and the tab's title were gone until the program set them again. Flashex now hands them to the helper as they change, so they are back with the terminal, also for a full-screen program such as vim or less, which then draws itself again where it was.
- **A terminal with a full-screen program keeps the shell's lines over a restart.** Quitting or restarting Flashex with vim, less or another full-screen program open brought the terminal back without what was above it; leaving the program showed an empty screen. The shell's lines are now kept and are there when the program ends.
- **Cmd+Q no longer quits by itself.** Three ways a quit could go through without the question about running programs, or with it answered for you: Cmd+Q pressed while the keyboard focus was on something that had just disappeared (or Quit chosen from the menu then) skipped the window altogether and kept the terminals silently; Cmd+Q held a moment too long opened the question and its own key repeat answered it; and with unsaved files that cannot be kept, the repeat counted as the second Cmd+Q that gives them up. Every quit you start now goes through the window, a held key never answers or confirms anything, and a second Cmd+Q answers the question only once it has been on screen for 0.7 s.
- **The notification after a quit from outside counts every running program.** When macOS or another program quit Flashex and terminals were kept, the notification counted only commands Flashex's shell integration had marked and Claude Code; a program in a shell without the integration is now counted too.
- **Resuming a Claude session uses the account it was started with.** If you start Claude Code through an alias or a variable for a second login (`claude-personal`, `claude-work`, `CLAUDE_CONFIG_DIR=~/.claude-work claude`, a wrapper function), everything in Flashex that starts the session again typed plain `claude`: the Resume offer after a restart, Resume Claude on a finished command, Reload Claude Session and the restart after a Claude Code update. The session was then looked for under your default account, where Claude said "No conversation found", and `--continue` could even pick another account's conversation. Flashex now remembers how each session was started (the alias, path or variables as you typed them, and the account folder Claude Code's hooks report) and types that again: `claude-personal --resume …`, or `CLAUDE_CONFIG_DIR=~/.claude-work claude --resume …` when only the account is known. Options you started with, such as `--model`, `--permission-mode` or `--dangerously-skip-permissions`, are kept; the first prompt and `-p` never are. `--continue` is used only when no other session of the same account may have run in that folder; when the account cannot be told, you pick from the list instead. With more than one account, the Resume offer, Resume Claude on a finished command and the Agents dashboard name the account ("personal"). A wrapper in front of `claude` (`op run -- claude`, `mise exec -- claude`, `caffeinate -i claude`) is typed again as it was. An alias is recognised once Claude Code's hooks are installed in its account (Settings › AI agents); a script that only ran a one-shot `claude -p` is not taken for one, and a `claude` started inside a running session does not take over its terminal. A variable that looks like a secret (`ANTHROPIC_API_KEY=…`) is never remembered, shown or typed again.
- **A resume that skips permissions says so.** When the session was started with `--dangerously-skip-permissions` (or `--permission-mode bypassPermissions`), the Resume offer after a restart says so as a warning, Resume Claude on the finished command reads "Resume Claude (permissions skipped)", and Reload Claude Session or the restart after an update types the line without running it, with a notice to check it and press Return. The same happens when a session was started through an alias whose name does not say Claude (`cc`, a script).
- **Pane sizes from an earlier version keep their proportions on another display.** Since 0.2.0 a dragged divider is remembered as a ratio, but a layout dragged in 0.1.5 or earlier was still stored as a fixed number of columns: moved from a wide monitor to a laptop, that pane kept its width and the pane beside it was squeezed to its minimum. The first time this version opens such a session it turns those fixed widths into ratios, exactly as the panes lie in the window, so nothing moves and from then on they shrink and grow together. A size set with the `size` command before this version becomes a ratio too (the two cannot be told apart in an old session): set it again and it stays fixed as before.
- **The System dashboard's chart reading is readable.** Pointing at a chart in the System dashboard showed only a sliver of the reading's box at the chart's left edge; the box now stands beside the point, with the time and the value in it, and moves to the point's left near the right edge.
- **A question in Settings is never cut off.** When a row at the bottom of the Settings list asked for confirmation on two lines ("Write Flashex's status line to ~/.claude-personal/settings.json?"), the second line was hidden under the card's footer. The list now scrolls so the whole question is in view.
- **A chart's reading no longer lands on other text.** Pointing at a chart in the System dashboard wrote the reading ("2m ago · 37%") under the chart's label, in a column too narrow for it: it ran over the chart, and in the stacked charts (network, disk) over the label of the chart below. The reading is now a small box inside the chart, next to the point you are on, that flips to the other side near the right edge and never leaves the chart; the label and the scale stay where they are. The Usage charts show their reading the same way.
- **The sidebar's chevron no longer covers a project's unread count.** With the list of terminals open, pointing at a project showed the chevron on top of the count (or the agent's dot) at the end of the row. A row with a count or a dot now has the chevron after it, with room of its own, still shown only under the pointer; a row without either keeps its whole width for the name and branch, as before.
- **A pane no longer jumps when an agent finishes in it.** A terminal that wants your attention (an agent finished or waits, a long command ended while you were looking elsewhere) gets a thicker green frame. That frame was laid out as a wider border, so everything in the pane, its tabs, the text and the prompt, moved a point to the right and down the moment the frame appeared and back again when you looked at the pane. The thicker frame is now drawn over the pane's edge and nothing in the pane moves.
- **The tab is no longer named after a Claude Code session that has ended.** Claude Code names its terminal ("✳ Claude Code", then the conversation's topic) and leaves the name there when it exits. With a shell that sets no title of its own, the tab, the sidebar row and the window kept that name until something else set one, long after the session was over. When a program that took the terminal over (Claude Code, another agent, a full-screen program) ends and its title is still there, the title from before it started comes back, usually none, so the tab names the folder again. A title your shell theme sets for the prompt stays, as does one set by a plain command or script, and a program you only suspended (`Ctrl+Z`) keeps its title.
- **The prompt after Claude Code exits is Flashex's again right away.** When you left Claude Code with `/exit` and Return, or with `Ctrl+C` or `Ctrl+D` twice, and the shell's prompt came back within a quarter of a second of that key, the prompt was shown as a bare terminal's: a block cursor instead of the prompt editor's, and the folder label at the right end of the prompt's row. It stayed that way until the next key or output. The same happened after any program that ends on a key (`q` in a pager). The prompt is now drawn again as soon as the key's short grace is over.

## [0.2.0] - 2026-10-13

A minimap and Settings by category, an Agents Timeline that shows who needs you, terminals that come back with what they showed after a restart, and a long round of fixes found by checking every screen by hand. macOS only; the Linux beta stays at 0.1.2 for now.

### Added
- **More settings in Settings (`Cmd+,`).** Editor › "Keep unsaved changes when quitting" (hot exit), Appearance › the window width under which a tab's panes show as a list, Terminal › memory for inline images and whether running agents and full-screen programs show as a plain terminal or as blocks. Each was only in `config.toml` before.
- **Pictures from files can be turned off.** Settings › Terminal › "Programs may show pictures from files" (`[terminal] image_files`, on by default) decides whether a program using the kitty graphics protocol may name a file on your Mac for Flashex to read and show; off, only pictures the program sends inline appear. It applies to new terminals.
- **Import a terminal color theme.** Settings › Appearance › "Import a terminal color theme" opens a file panel: pick a theme file (`key = value` lines such as `background = #1e1e2e` and `palette = 1=#f38ba8`, the format many terminal themes come in) and Flashex copies it into its themes folder and uses it right away. Terminal colors then shows "Custom". A file that sets no colour, is not text or is over 1 MB is refused with the reason.
- **Your own duration as Keep Mac Awake's default.** Settings › General › "Keep Mac Awake: default mode" now also offers **Custom**: the duration you typed last in the chooser (such as `1h30` or `until 18:30`) is then preselected, and `toggle_keep_mac_awake` starts it, reading it afresh each time (`[general] keep_awake_mode = "custom"`).
- **Keep Mac Awake after a restart.** When Flashex restarts (an update, Restart Flashex, a crash) while Keep Mac Awake is on, a notice offers **Keep Awake** to go on: a timed mode for the time it had left, "until I turn it off" and "while agents run" if Flashex was gone only a short while. It never turns on by itself.
- **Pull, Push and Sync from the Git menu and the command palette.** Git › Pull, Push and Sync (pull, then push) run in the active project's repository just as Source Control's buttons do, without opening the panel; in the palette they are "Git: Pull", "Git: Push" and "Git: Sync". **Go to Folder…** is now in the Terminal menu too. All four can get their own shortcut in `keybindings.toml` (`git_pull`, `git_push`, `git_sync`, `go_to_folder`).
- **Pictures' paths in the terminal preview on hover.** When Claude Code or any other program prints a picture's path (`Saved screenshot to ./shots/a.png`, `~/Desktop/x.jpg`, `` `chart.svg` ``, `![chart](out/c.png)`, `file:///…/a.webp`, `my\ shot.png`, or a macOS screenshot name with spaces), pointing at it underlines it once the file is found (relative paths are looked for in the terminal's folder, then the project's). Rest the pointer there for a moment and a small preview shows above or below it with the file's name, its size in pixels and on disk; it goes away when you move off, scroll or type. PNG, JPEG, GIF, WebP, BMP, TIFF, ICO and SVG are shown; files over 30 MB or pictures over 50 megapixels show only their details. `Cmd+click` opens the picture in the editor pane beside, and a right click offers **Open**, **Reveal in Finder**, **Copy Path** and **Copy Image**. In a program that uses the mouse, hold `Cmd`. The preview can be turned off in Settings › Terminal ("Preview pictures on hover") or with `[terminal] image_hover_preview = false`.
- **The Usage dashboard explains its terms.** Words with a dashed underline, such as pace, sustainable, the run-out forecast, the daily budget, median and p90, cache lifetime or where the limits come from, say what they mean when you point at them.
- **Agents Timeline: who needs you, at a glance.** Sessions waiting for you are always at the top, highlighted, with how long they have waited ("waiting 4 min · needs permission: Bash"); sessions at work follow, each with what it is doing right now ("Edit system_view.rs", "Bash: cargo test") and, when its transcript was read, its context ("84.0K · 42%"). Idle and ended sessions fold into one "▸ 5 finished" row with small strips of their activity, and a session's subagents fold into "▸ 3 subagents" under it; a click unfolds them, and a session that gets busy again moves back up by itself. A strip above the lanes counts sessions working, waiting and finished and sums how long agents waited on you today.
- **Agents Timeline: errors, details and the way back.** Failed tool calls and denied permissions show as red dots on their lane (read from the session's transcript). Pointing at a stretch or a mark shows a tooltip with what it was, the tool, how long it took and when; clicking a lane, a subagent's too, takes you to that session's terminal, bringing its project and tab to the front. Chips filter the timeline to one project, and the chosen window (15m / 1h / 4h), project and the finished fold are remembered across restarts.
- **`flashex keeper status`.** Lists the restart keepers that keep your terminals running across a crash or a restart, and what each holds: the app it belongs to, how many terminals it keeps and how many still run, and while it waits for the app to come back, how much output it has saved. It asks the keepers directly, so it works while Flashex is not running; `--json` gives the same as JSON.
- **Terminals come back with what they showed after a restart.** After "Restart Flashex" or an update, a terminal used to come back with only what its program printed while Flashex was away, and a blank screen above it. It now shows the lines it had (its screen and up to 500 lines of history, without colours), the cursor where it was, and then what came meanwhile. A full-screen program such as vim draws itself again as before.
- **Menus work from the keyboard.** The "+ ⌄" menu, the "»" list of tabs that have no room, the sidebar's right-click menu and the file tree's right-click menu now take ↑/↓ to choose a row and Enter or Space to run it, like the "?" menu; Esc or any other key closes them as before. In the file tree's question (Move to Trash, Discard Changes and the like), ←/→ or Tab put a focus ring on Cancel or the other button and Enter presses it; `Cmd+Enter` and Esc work as before, and a plain Enter with no button chosen still does nothing.
- **Popovers' buttons from the keyboard.** In the Claude Code restart popover (the refresh icon, Reload Claude Session) and the AI answer popover, ←/→ or Tab put a focus ring on a button and Enter or Space presses it; Esc closes them as before. Enter does nothing until a button is chosen, so a stray Enter never restarts a session.
- **Select text in the AI answer.** The Explain and Fix popover's answer can now be selected with the mouse (an I-beam over its text; drag across paragraphs, list items and table cells), `Cmd+A` selects the whole answer and `Cmd+C` copies the selection. Code blocks keep their own Copy button.
- **Only web servers next to a project, as a small globe chip.** The sidebar no longer shows every port a project's programs listen on (a bare `:50213` was often an agent's IDE bridge, a debugger or Node's inspector). Flashex asks each new port once, with a short HTTP request on a background thread, and shows only the ones that answer like a web server. They appear as a quiet chip with a globe and the port that brightens when you point at it; its tooltip says what a click does and which program serves it ("Open localhost:5173 in a browser panel — served by node"). With several servers the chip shows the first and "+2", which lists the others and lets you choose one. In a narrow sidebar the chip is just the globe. **Open Port in Browser…** in the command palette lists the same servers.
- **Reload Claude Session asks next to its terminal.** When Claude Code is busy and Reload Claude Session comes from the command palette or its shortcut, the question now opens under that terminal's pane tab instead of at the top of the window (it stays at the top when the tab is not on screen).
- **Panes reach the bottom of the window.** The panes used to end a few pixels above the status bar, short of the sidebar's foot, whenever the window's height was not a whole number of text lines; the same sliver was left at the right edge. Panes on the bottom and right edges now take that room, so they line up with the sidebar.
- **Explain, Fix and Send to hide secrets in the output too.** A command's output sent to an agent or an AI provider now has passwords, tokens and keys replaced with `***`, as its command line already had (`TOKEN=…`, `--password …`, `user:password@` in URLs, well-known API tokens and long random strings). Commit ids and checksums stay readable.
- **A block's bar in a narrow pane keeps Fix.** When a failed command's bar has no room for everything, the agent's chip ("Claude 2") now goes before a tool does, so you get "Explain" and "Fix" side by side instead of "Explain · Claude 2" with Fix hidden in "⋯". The tooltip still says where each one goes.
- **"Send to…" tells agents in one tab apart.** With two agents in split panes of the same tab, the list named both "Claude (tab 2)"; the second is now "Claude (tab 2) · 2".
- **Failed tools reach the Agents Timeline at once.** Flashex's Claude Code hooks now also listen for a failed tool call, so its red dot appears the moment it fails (with the command or file it was about) instead of after the transcript is read. The hooks update themselves when Flashex starts if your Claude Code is 2.1.119 or newer (otherwise Settings › AI agents offers the update); a failure reported by both the hook and the transcript is one dot, which turns into "Permission denied" when the transcript says so.
- **Language, indentation and line endings from the status bar.** With an editor focused, click its language to pick another one for its colours (or Auto Detect, or Plain Text); click the indentation to choose what Tab inserts (2, 4 or 8 spaces, or a tab) or to convert every line's leading indentation to spaces or tabs; click LF or CRLF to change the line endings the file is saved with. Converting and changing line endings are one step each to undo.
- **HEIC pictures.** iPhone photos and other HEIC / HEIF pictures (`.heic`, `.heif`, or told by their contents) now open in an image tab with their size, preview on hover when a terminal prints their path, and can be copied with **Copy Image**; macOS decodes them.
- **Terminal rows in the sidebar: a menu and dragging.** Right-click a terminal's row under a project for **Rename** (give the terminal a name of its own; an empty name gives it back to its program) and **Close**, also from the keyboard like the sidebar's other menus. A row of the tab on screen can be dragged into a pane or its tab strip, as its pane tab can.
- **Close and reorder panes in a tab shown as a list.** Each row of the list has a × (shown on the selected row and on hover, a dot while a file in it is unsaved) that closes that pane with its tabs, asking first when something still runs; drag a row before or after another to change its place.
- **Pick a custom project colour with the mouse.** "Custom…" in a project's or group's colours now shows a colour square and a hue bar under the hex field; click or drag in them and the field and the swatch follow. Typing a hex value works as before.
- **Settings by category.** A bar at the top of Settings (`Cmd+,`) jumps to Appearance, Terminal, Editor, AI, Browser or General, and marks the category you are reading as you scroll; `Cmd+]` and `Cmd+[` go to the next and the previous one. In a narrow window the bar shows only its icons (the name in a tooltip). The sections are grouped under them: Language Servers and Source Control under Editor, AI agents with AI, and Keyboard, Notifications, Session and Updates under General.
- **A minimap in the code editor.** An editor pane wide enough for a hundred columns of text beside it shows the file drawn small on its right edge, in its syntax colours, with the part on screen as a light slider. Click it to jump there, drag the slider to scroll; the mouse wheel scrolls as over the text. It hides in a narrower pane and is not shown in a diff. Settings › Editor › "Minimap (wide panes)" or `[editor] minimap = false` turns it off.

### Changed
- **The branch line in the sidebar uses the whole row.** The chevron that folds a project's list of terminals no longer keeps an empty space at the end of the project's row; it appears over the row's end while you point at the row. A long branch name is now cut much later, and the counts and the web server chip stay whole as before. A folded list still shows its chevron all the time.
- **Line numbers sit in the middle of the editor's gutter**, as in Sublime Text, instead of against its right side; the current line's number is still brighter, and error dots and change marks stay at the gutter's edges.
- **Keep Mac Awake is set where you turn it on.** Settings no longer has a General section with Keep Mac Awake's rows. Its chooser (Cmd+K › Keep Mac Awake…) remembers what you pick there: the mode you start becomes the one preselected next time ("last used") and the one `toggle_keep_mac_awake` starts, and the Display and Screen lock toggles under its rows are kept for the next time too. ### Changed
- **The line numbers in the editor no longer push the text as a file grows.** The gutter keeps room for four digits from the start, so typing past line 9, 99 or 999 never shifts the code sideways; a file of ten thousand lines or more is as wide as it needs from the moment it opens, not when you scroll down. The numbers also have more room on both sides, like in Sublime Text, with the error dot on the left and the git change bar on the right. The diff view uses the same width.
- **Ended sessions leave the Agents list.** Sessions that ended move out of the live list into a folded **Recently ended** section at the bottom for 15 minutes, and the new **Ended** chip lists every ended session the dashboard still remembers. Finished subagents fold into one "3 finished" row under their session (click it to see them, dimmed).
- **A top tab is shown when you click it**, not as soon as the button goes down, so dragging an inactive tab into a pane leaves the tab you see in view.

### Fixed
- **Notifications show the Flashex icon after an in-app update.** The update unpacks the new version into a hidden folder next to the app first, and macOS could keep a record of the app at that folder after it was gone, so a notification looked for the icon there and showed a blank white square. The updater now tells macOS to forget the unpacked copy before it moves it into place or removes it, and the app registers itself with macOS once after it was updated or moved.
- **The Agents dashboard scrolls.** With more sessions than fit, the list now scrolls with the trackpad or mouse wheel, and ↑/↓ keep the selected row in view.
- **Sessions that are gone no longer stay open in the Agents dashboard.** A session now ends when its terminal is closed, when the shell's prompt comes back (Claude Code exited, crashed or was killed without telling), or when the terminal reports Claude Code ended, even if its last hook event never arrived. A subagent interrupted with Esc no longer stays "running" forever: it ends with its turn (subagents started in the background go on until they finish).
- **Claude Code and other agents run in a plain terminal, not inside a command block.** While Claude Code, Codex, Gemini or another program that draws its own screen in the terminal (it turns on bracketed paste, focus reports, the mouse or the alternate screen) is running, Flashex no longer draws block decorations over it: no grey bar down the left edge, no line above it, no running time in the corner and no block tools or "⋯" appearing wherever the pointer is. The mouse over it is the program's. When Claude Code redraws its whole screen (on resize or a long answer), the leftover line and timer no longer float on an empty row below its prompt box, and once it exits the whole conversation is one finished block again, with its header, Resume Claude and Copy output, instead of the block vanishing. The text never moves when it starts or ends. `[blocks] tui = "blocks"` in `config.toml` brings the old look back.

## [0.1.3] - 2026-10-10

macOS only. The Linux beta stays at 0.1.2 for now.

### Added
- **Keep Mac Awake.** A built-in `caffeinate` in the command palette (Cmd+K › Keep Mac Awake…): keep the display and your Mac awake, with no screen saver and no idle screen lock, **for 1, 2 or 4 hours**, **until you turn it off**, or **while agents are running** (on while any Claude Code session is running or waiting for you, off three minutes after the last one goes idle). A cup in the status bar shows the time left; click it to extend by an hour, change the mode or stop. It turns off by itself when the time is up, when you choose Stop Keeping Mac Awake, and when Flashex quits; if Flashex ever crashes, macOS drops it with the app. Closing the lid on battery still puts the Mac to sleep, as macOS requires. The mode picked by default is in Settings › General, and it never turns on by itself. Bind `keep_mac_awake`, `stop_keeping_mac_awake` or `toggle_keep_mac_awake` in `keybindings.toml` for a shortcut. macOS only.
- **System Dashboard.** A new pane (Cmd+K › System Dashboard) shows what this Mac is doing, a native port of flash-top: **CPU** (total, user and system, every core in its efficiency and performance cluster, load average), **Memory** (used, app, wired, compressed, cached, memory pressure, swap), **GPU** (load, renderer and tiler, memory), **Disk** (space on the data volume, reads and writes, and when it fills up if it keeps filling), **Network** (the link and its addresses, download and upload, each interface with its totals, and the processes using the network most), **Temperatures** (CPU and GPU, SSD, battery, the hottest sensor), the **battery** (charge, time left or to full, power, health, cycles) and the **top processes** by CPU and by memory. Charts show a fixed window of the last five minutes ("-5m … now"), new samples coming in on the right; right after you open the dashboard the part not collected yet is shaded and marked "collecting…". Each chart says what it plots ("CPU %", "Memory used") and its scale uses round steps (25, 50 or 100 %, "5 MB/s"); point at one to read a value. The cards line up in rows of equal height, in as many columns as the pane is wide. `r` reads everything now, `h` explains every number and where it comes from. Nothing needs administrator rights and nothing leaves your Mac: the dashboard reads only while it is on screen. **Public IP** in its header (off by default) shows the address the internet sees, asking api.ipify.org every five minutes while it is on. On Linux CPU, memory, disk, network and processes come from `/proc`; GPU, temperatures and battery say "macOS only".
- **Usage Dashboard.** A new pane (Cmd+K › Usage Dashboard) shows your Claude Code usage across every session on this Mac. **Rate limits:** the 5-hour and weekly limits, how much is used and when each resets, how fast you are using them against the pace that would last until the reset, and a forecast ("On track", "Tight", or when it runs out); once a limit is spent, when it was hit. **Throughput:** tokens per second, latency and output tokens as charts over 1 to 24 hours, with the value under the pointer. **Today:** requests, tokens and how much input came from the prompt cache. **Breakdown:** output and speed per model and per project, and the open sessions with their prompt cache (warm or expired). A **Help** card (or `h`) explains every number; `w` changes the window, `r` reads the transcripts again. Rate limits come from Claude Code's status line: the dashboard shows the few lines to add to your status-line script and a **Copy** button (Flashex never edits it), and a status line set up for cc-meter works as it is. Optional, all off by default: **Show Claude status** (status.claude.com's incidents and components), the 5-hour limit in the status bar ("5h 62%", Settings › AI agents), a notice when a limit reaches 90 %, and asking Anthropic's usage API when no status line has reported the limits (Settings › AI agents; it uses Claude Code's login from the Keychain only when on). Everything else stays on your Mac; the dashboard reads only while it is on screen and keeps a small summary so it opens fast next time.
- **Agents Dashboard.** A new pane, opened from the command palette (Cmd+K › Agents Dashboard), shows every Claude Code session in the window: its project, folder and terminal, whether it is waiting for you, running, idle or ended, what it is doing right now ("Bash cargo test", "Edit src/parser.rs", "waiting: needs permission: Bash"), for how long, its model and how full its context is. Each session's subagents are listed under it with their task, their current tool and their own model and context. Sessions waiting for you come first. Filter by All, Running or Waiting, or just type to filter; ↑/↓ and Enter jump to a session's terminal (a click does too), Space folds its subagents. The selected session offers **Reload**, **Interrupt** (sends Esc to its terminal after asking) and **Transcript** (opens the conversation log read-only). The dashboard opens as a tab of the current pane, can be split, moved and closed like any pane, and comes back after a restart. Everything stays on your Mac: it reads only Claude Code's hook events and, while the dashboard is on screen, the model and token counts from the session transcripts. If Claude Code's hooks are not installed, the dashboard offers to install them.
- **Add a project straight to a group.** The New project dialog has a **Group** field under the folder search: Tab and Shift+Tab (or a click) step through your groups and "No group". It starts on the group you opened it from, otherwise on the current project's group. The project goes at the end of that group, and a folded group opens to show it. A group's header has a **+** (on hover, always for an empty group) that opens the dialog with that group chosen, an empty group shows an **Add a project…** row, and a group's right-click menu has **Add Project…**.
- **Keep notifications on screen.** How long a banner stays is set by macOS, not by the app: Settings › Notifications now has **Keep notifications on screen** with an **Open** button that takes you to System Settings › Notifications › Flashex, where **Alerts** keeps them until you dismiss them.
- **Reload Claude Session.** A new command palette entry (Cmd+K) restarts Claude Code in the focused terminal and resumes the same conversation, with the options it was started with, whether or not a newer version is installed. Handy after changing Claude Code's settings, plugins or MCP servers. If Claude is working, you choose **Restart when idle**, **Restart now** (which interrupts the running task) or **Cancel**, as with the update icon. **Reload All Idle Claude Sessions** does the same for every idle session and leaves busy ones alone. Both appear only where Claude Code runs and have no shortcut by default; bind `reload_claude_session` or `reload_idle_claude_sessions` in `keybindings.toml`.

### Changed
- **Terminal colors.** Settings › Appearance › Terminal colors picks Flashex's own colour schemes: Flashex, Graphite, Harbor or Ember, each with a dark and a light variant that follows the Theme row. A theme file you named in `config.toml` keeps working and shows as Custom.

## [0.1.0] - 2026-10-08

The first public release, for Apple Silicon Macs with macOS 13 or later.

### Added

**Terminal**
- `flashex-vt`, Flashex's own terminal core written in Rust. It passes 450 of 567 esctest2 tests, and has run for hours of fuzzing without a failure.
- Inline images: the kitty graphics protocol, sixel and iTerm2 images, which scroll with the text.
- The kitty keyboard protocol, SGR-pixel mouse reports, XTGETTCAP and the window-title stack.
- Command blocks: each command shows with its folder, duration and exit code. You can jump between blocks, select, fold, copy or rerun a block, or save it as a workflow.
- Shell integration for zsh, bash and fish, set up automatically. Its marks are signed so programs can't fake them.
- A compact prompt with a clickable path. Click the path to open the folder or to switch to a nearby one.
- Find in the terminal, including the scrollback.
- Splits, zoom, tabs inside a pane, layout presets and a quick layout switcher. New splits start in the focused terminal's folder.

**AI agents**
- Claude Code hooks (`flashex setup claude`) report when an agent is running, waiting for you or done.
- The sidebar shows each agent's state as a dot. Notifications point at the exact terminal, and the notification center lists what happened.
- A finished Claude Code session can be resumed from its command block.

**Editor**
- Tree-sitter highlighting.
- Multi-cursor editing in the style of Sublime Text and VS Code.
- Language-server features from the servers you have installed: go to definition, references, hover, completion, rename and diagnostics.
- Markdown preview.
- Hot exit: unsaved and untitled files survive a quit, a crash or a restart.

**Projects and Source Control**
- Projects and groups in the sidebar, with the branch and git state shown as `↑` ahead, `↓` behind and `±` changed files. Hover the marks to see what they mean.
- Source Control: stage, unstage, discard, commit, pull, push and switch branches, with side-by-side diffs against HEAD.
- A file tree, a palette (`⌘K`) and a keyboard shortcuts sheet (`⌘?`). Shortcut labels follow your keyboard layout.
- A browser panel for local pages.

**App**
- A restart keeper. A tiny helper process holds your terminals while Flashex restarts after an update or a crash, so shells, agents and running jobs carry on. Quitting with `⌘Q` still ends everything, and the keeper stops on its own after a grace period.
- In-app updates. Flashex checks for a new version at start and once a day, and shows a quiet card in the corner of the window. Nothing is installed until you click Update and then Restart Now. Updates are signed with Flashex's own key and checked before they are installed. You can also check by hand from the `?` menu, the app menu or the palette.
- Animations for splits, zoom, tabs, the sidebar and popups. Turn them off in Settings; they also follow macOS Reduce motion.
- Light and dark themes with a choice of accent colour.
